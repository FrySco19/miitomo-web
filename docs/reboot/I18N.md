# Reboot — languages (R5): English and Italiano

Every new Reboot text goes through one table (`client/web/src/reboot/i18n/`). Components never branch on the
language; a unit test fails if one does.

## Choosing the language

1. The user's choice, stored as `mtw.reboot.lang` (Piazza header, MiiPhone home screen).
2. Otherwise the browser's languages, in order (`it-CH` → Italiano).
3. Otherwise English (fallback).

A change applies at once (every Reboot view re-renders) and survives a reload. If storage is refused (private mode)
the choice holds for the session.

## Texts

- `strings.ts`: one table per language with the **same keys** (tested), the same placeholders (tested), nothing
  empty (tested). `{name}` placeholders, `key.one` / `key.other` plurals, `@other.key` for a translated value inside a
  sentence (a personality name in a quiz question).
- A missing key falls back to English, then to the key itself — visible in tests, never a crash.
- Texts produced by the Miis (MIInstagram moments and comments, quiz questions) are stored as data (key + values),
  so they read in the language of the moment, not in the one they were created in.
- The R4 Italian texts of the Piazza are kept word for word.

## What is translated

Piazza, friends' rooms, Sala Giochi and the Quiz dei Mii, MiiPhone, MIInstagram, the place bar, every error and empty
state of these. **Not** translated: Classic (it shows the original texts of the user's files) and the R1–R3 Reboot
panel ("Reboot" pill), which stays Italian for now.

## Tests

`tests/unit/i18n.test.mts` (detection, fallback, manual choice, persistence, corrupt / refused storage, placeholders,
plurals, nested values, both tables complete, every key used by the code present, every dynamic key family complete,
no language branches, no hard-coded sentences in the R5 views) · scenario H in the R5 E2E suites.
